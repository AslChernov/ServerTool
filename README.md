# ServerTool

Интерактивная настройка, защита и ручная очистка серверов Ubuntu/Debian. Два профиля: **нода Remnawave** и **универсальный сервер** для панели, сайта, API, бота или другого установленного софта.

## Что умеет

- обновляет систему;
- предлагает выбор профиля в пункте 1 и сохраняет его для последующих запусков;
- проверяет место и inode перед обновлением и восстановлением пакетов;
- очищает кэш, просроченные временные файлы, архивные журналы и выбранные старые резервные копии;
- отдельно очищает Docker build cache и висячие образы без удаления контейнеров и volumes;
- устанавливает единый входящий firewall на nftables без UFW;
- для ноды открывает `443/tcp`, `443/udp` или оба протокола на выбор;
- для универсального сервера поддерживает публичные TCP/UDP-порты, ограничения по IP/CIDR и IPv6;
- управляет дополнительными публичными TCP/UDP-портами через меню с сохранением настроек;
- разрешает API-порт ноды (по умолчанию `2222/tcp`) только с IPv4/CIDR панели;
- фильтрует как локальный трафик, так и опубликованные Docker-порты;
- закрывает неизвестные Docker DNAT-публикации;
- объединяет и схлопывает Anti-Scanner/government/Geo-IP списки;
- хранит проверенный кэш списков для загрузки firewall без интернета;
- опционально устанавливает CrowdSec с nftables-bouncer и защитой SSH/Nginx;
- ограничивает память CrowdSec в зависимости от ОЗУ сервера;
- добавляет публичный SSH-ключ или генерирует Ed25519-пару;
- переводит SSH на случайный или указанный порт с синхронным обновлением firewall и откатом;
- устанавливает XanMod LTS/Main и включает BBR + `fq`;
- делает резервные копии firewall и SSH-конфигурации.

TrafficGuard, CTGuard и BanOnce не устанавливаются. Из TrafficGuard используются только публичные IP-списки. Скрипт не выполняет глобальный `nft flush ruleset` и не изменяет таблицы Docker/CrowdSec.

## Запуск

```bash
sudo apt-get update && sudo apt-get install -y curl
curl -fsSL https://raw.githubusercontent.com/AslChernov/ServerTool/main/server_tool.sh -o server_tool.sh
chmod +x server_tool.sh
sudo ./server_tool.sh
```

Просмотр состояния без меню:

```bash
sudo ./server_tool.sh --status
```

## Рекомендуемый порядок

1. Сделайте snapshot и оставьте открытой резервную консоль хостинга.
2. В пункте **1** выберите **ноду** или **универсальный сервер**.
3. Проверьте диск, при необходимости воспользуйтесь пунктом **11**.
4. Добавьте SSH-ключ, настройте SSH и проверьте новый вход, не закрывая текущую сессию.
5. Настройте firewall с нужными портами и проверьте доступ из другого окна.
6. При необходимости установите CrowdSec и включите BBR на текущем ядре.

Профиль сохраняется в `/etc/server-tool/profile`. Установки без этого файла считаются нодовыми. Выбор профиля сам по себе не переписывает действующий firewall: его нужно настроить соответствующим шагом мастера или пунктом 3. Статус показывает отдельно выбранный профиль и профиль конфигурации firewall.

Для **ноды** сохраняется API-порт, доступный только с IPv4/CIDR панели; мастер также предлагает XanMod. Для **универсального сервера** отсутствуют обязательные порты Remnawave: мастер показывает слушающие сервисы и Docker-публикации, затем запрашивает публичные порты, источники SSH и правила вида «протокол + порт + IP/CIDR». Например: `80 443/tcp` публично, `9090/tcp` только с IP мониторинга. Порты автоматически не открываются. При включении IPv6 публичные разрешения действуют для обеих версий IP; ограничения задаются отдельными IPv4/IPv6 CIDR.

Универсальный мастер не устанавливает Docker, reverse proxy, базу или приложения и не предлагает замену ядра. Эти программы могут быть любыми. Обновление универсального сервера сначала показывает изменения и не разрешает APT удалять установленные пакеты. Удаление ненужных пакетов вынесено в меню очистки для обоих профилей.

## Архитектура firewall

ServerTool управляет только таблицей `inet server_tool_guard`:

- `input` имеет политику `drop`;
- разрешены loopback, установленные соединения, ICMP и SSH; остальные порты зависят от выбранного профиля;
- контейнерам разрешено инициировать исходящие соединения к хосту и другим сетям;
- `forward` проверяет исходный порт до Docker DNAT;
- неизвестные опубликованные Docker-порты блокируются;
- основной firewall загружается из локального кэша до запуска Docker;
- списки обновляются отдельным systemd-таймером раз в сутки.

В нодовом профиле IPv6-службы наружу не открываются. В универсальном профиле IPv6 выбирается при настройке; ICMPv6 разрешён для корректной работы сетевого стека. Внешние Anti-Scanner/IP-списки для универсального сервера изначально выключены и включаются только по выбору; разрешённый SSH не блокируется этими списками. CrowdSec применяет свои решения отдельно.

Перед первоначальной или повторной настройкой создаётся резервная копия правил и файлов ServerTool, а через systemd планируется откат через 5 минут. После применения нужно проверить новый SSH-вход и нужные сервисы из другого окна и в течение 120 секунд ввести `yes`. При ошибке, отказе или потере сессии восстанавливаются прежняя таблица ServerTool, файлы и состояние сервисов. Другие nftables-таблицы не очищаются. После подтверждения откат отменяется, затем по выбору обновляются IP-списки.

Активный UFW отключается только после отдельного подтверждения и восстанавливается при откате; пакет UFW не удаляется. При активном firewalld мастер отказывается от замены до ручного согласования правил. Чужие nftables-таблицы могут дополнительно ограничивать доступ, даже если ServerTool разрешает порт. Firewall хостинга настраивается отдельно.

## Дополнительные порты

В главном меню выберите **10 → Открыть свой порт** (также доступно через **5 → 6**).
Введите номер порта и выберите TCP, UDP или оба протокола. Например, для входа
Turkey через BRIDGE-ноду: **8443 → TCP → подтвердить**.

- Показан текущий список дополнительных TCP- и UDP-портов; отдельный пункт убирает разрешение.
- Порты публичны с учётом IP-блокировок ServerTool и CrowdSec; в универсальном профиле с IPv6 — для обоих семейств IP.
- Разрешение распространяется на хост и Docker-публикации, где проверяется внешний порт до DNAT.
- В нодовом профиле SSH-порт, API-порт ноды и `443` меняются только через основные настройки: открыть API ноды для всех этим меню нельзя. В универсальном профиле зарезервирован только SSH-порт; публичное разрешение для порта с ограничением по IP отклоняется.
- До применения создаётся резервная копия и выполняется `nft --check`; при ошибке применения восстанавливаются прежние файлы и правила.
- Сохраняются текущие настройки SSH, API, IP панели и остальные параметры конфигурации.
- На старой установке достаточно скачать новый `server_tool.sh` и воспользоваться пунктом 10: он обновит установленный генератор правил. Повторно проходить мастер firewall не нужно.

Списки хранятся в `/etc/server-tool/guard.conf`:

```bash
EXTRA_TCP_PORTS="8443 9443"
EXTRA_UDP_PORTS="5353"
```

Они сохраняются после перезагрузки, ежедневного обновления списков и повторной
настройки firewall новой версией ServerTool. Старые конфиги без этих полей
работают как раньше. Откат на старую версию ServerTool не поддерживает новые поля.

Удаление дополнительного разрешения не разрывает уже установленные соединения.
Открытие порта не запускает сервис и не изменяет настройки firewall у хостинга —
при наличии внешнего firewall порт нужно разрешить и там.

## CrowdSec

CrowdSec устанавливается только по выбору пользователя:

- используется официальный репозиторий CrowdSec;
- включаются коллекции Linux, SSH и Nginx;
- в нодовом профиле скрипт пытается найти `remnawave-nginx`;
- в универсальном профиле выбираются Linux/SSH, журналы Nginx на хосте или Nginx-контейнер с указанным именем;
- nftables-bouncer создаёт отдельную таблицу `ip crowdsec`;
- штатные nftables-hook’и `input` и `forward` применяют решения CrowdSec к хосту и Docker-трафику;
- LAPI остаётся на loopback-порту `8080`, а при конфликте автоматически переключается на свободный порт `18080–18089`;
- systemd ограничивает память и снижает вероятность убийства CrowdSec через OOM.

Универсальный профиль также включает IPv6 в nftables-bouncer. Поддержка произвольного приложения требует совместимого парсера и подходящих журналов; одна установка CrowdSec не означает защиты логина любого установленного софта.

CrowdSec не является защитой от объёмного DDoS — она должна предоставляться хостингом.

## Ручная очистка

Главное меню → **11**. Никаких таймеров или расписаний очистки не создаётся. Доступны:

1. Диагностика разделов, inode, крупных каталогов `/var` и `/opt`, журналов и использования Docker.
2. Скачанный кэш APT и просроченные временные файлы по штатным правилам `tmpfiles.d`. Очистка `/tmp` целиком не выполняется.
3. Ротация systemd journal и удаление старых архивов до выбранного лимита (по умолчанию 200 МиБ). Это безвозвратно сокращает историю; активный журнал может занимать дополнительное место.
4. Docker build cache и висячие образы без тегов, не связанные с контейнерами, с отдельным подтверждением. Контейнеры, volumes, сети и tagged images не удаляются. Следующая сборка может стать медленнее; старый образ может быть нужен для отката.
5. Старые резервные копии с предварительным списком путей и размеров.
6. Предварительный просмотр APT autoremove; при предложении удалить работающее или новейшее резервное ядро операция отклоняется. Пакеты не удаляются при незавершённом состоянии dpkg.
7. Ручное восстановление прерванного `dpkg` после освобождения места.

Для копий **ServerTool** обрабатываются только известные каталоги `YYYYMMDD-HHMMSS-ssh`, `YYYYMMDD-HHMMSS-firewall` (включая новые имена с уникальным суффиксом `.XXXXXX`) и `ports.XXXXXX` с ожидаемыми файлами. По умолчанию удаляются копии старше 30 дней, при этом сохраняются **минимум три последних копии каждого типа**.

Для **другого приложения** нужно явно указать отдельный каталог и шаблон завершённых архивов одного приложения (например, `*.tar.gz` или `database-*.sql.gz`). Сохраняются три последних подходящих файла. Поддерживаются `.tar`, `.tar.gz`, `.tgz`, `.tar.xz`, `.tar.zst`, `.zip`, `.sql`, `.sql.gz`, `.dump`, `.bak`; файлы с окончанием `.partial`/`.tmp` не выбираются. Символические ссылки, системные каталоги, точки монтирования и обнаруженные открытые файлы исключаются. Перед удалением список проверяется повторно: при изменении кандидатов операция отменяется. Не запускайте очистку одновременно с созданием или восстановлением бэкапов. Без отдельной резервной копии удалённые архивы не восстановить.

После операции показывается состояние разделов и прирост свободного места на корневом разделе. Если данные лежали на другом разделе, результат виден в `df` для соответствующего раздела.

## Важные замечания

- По умолчанию API ноды доступен только с `45.148.62.18`; значение меняется в меню.
- Geo-block по умолчанию выключен.
- Слишком широкие, приватные и локальные сети из внешних списков отбрасываются.
- Подозрительно пустое обновление не заменяет рабочий кэш.
- Если APT занят фоновым обновлением, скрипт ждёт освобождения блокировки до 5 минут и не удаляет lock-файлы.
- При незавершённой настройке пакетов скрипт один раз запускает штатное восстановление `dpkg --configure --pending` и `apt-get --fix-broken install`, а полный вывод ошибки сохраняет в журнал.
- Перед обновлением/восстановлением проверяется рабочий запас: 512 МиБ для корня и APT, 32 МиБ для `/tmp`, 128 МиБ для отдельного `/boot` и 1024 свободных inode, если файловая система их учитывает. Фактическому обновлению может потребоваться больше места.
- При `No space left on device` предлагается очистить только кэш APT и повторить команду один раз. До освобождения места восстановление dpkg не запускается; журналы и бэкапы автоматически не удаляются.
- При переносе CrowdSec LAPI скрипт синхронизирует `api_url` установленного nftables-bouncer, сохраняя его API-ключ и остальные параметры.
- Настройки LAPI, созданные ServerTool, хранятся в поддерживаемых CrowdSec `.yaml.local`-файлах; существующие пользовательские оверлеи не перезаписываются.
- Приватный ключ, созданный на сервере, нужно скачать, проверить и удалить с сервера.
- Скрипт не перезагружает сервер автоматически.
- XanMod проверяется по HTTPS для кодового имени установленной ОС. Сетевой сбой не считается доказательством отсутствия поддержки: вывод curl показывает причину, при ошибке соединения выполняется ограниченный повтор через IPv4. Ключ проверяется во временном файле до замены установленного keyring. При ошибке обновления индексов или отсутствии выбранного пакета прежние source/keyring восстанавливаются; после начала установки проверенный репозиторий сохраняется для восстановления APT. Неудача необязательной установки XanMod не завершает весь мастер; повторить её можно отдельно через пункт 7.

## Файлы на сервере

| Назначение | Путь |
|---|---|
| Выбранный профиль | `/etc/server-tool/profile` |
| Настройки firewall | `/etc/server-tool/guard.conf` |
| Проверенный кэш IP | `/var/lib/server-tool/blocklist-v4.txt` |
| Применение firewall | `/usr/local/sbin/server-tool-guard-update` |
| SSH-настройки | `/etc/ssh/sshd_config.d/00-server-tool.conf` |
| Выбранный порт CrowdSec LAPI | `/etc/server-tool/crowdsec-lapi-port` |
| Резервные копии | `/var/backups/server-tool/` |
| Лог | `/var/log/server-tool.log` |

## Поддержка

- Ubuntu 24.04 LTS и Debian 13 рекомендуются;
- другие актуальные Ubuntu/Debian также проверяются скриптом;
- amd64 обязательна только для XanMod;
- запуск от `root`/через `sudo`.

Источники: [XanMod](https://xanmod.org/), [CrowdSec](https://docs.crowdsec.net/u/getting_started/installation/linux/), [Docker firewall](https://docs.docker.com/engine/network/packet-filtering-firewalls/) и [Ubuntu OpenSSH](https://documentation.ubuntu.com/server/how-to/security/openssh-server/).
